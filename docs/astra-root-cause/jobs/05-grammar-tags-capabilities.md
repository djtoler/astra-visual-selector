# Job 5 — Grammar, tags and template-capability coverage

## One job

Evaluate whether the grammar can express the visual jobs the stories require and
whether template metadata accurately exposes every existing family's reusable
communication capability.

## Evaluate

- Legacy jobs in `grammar/JOBS.md` versus current presentation operations.
- Relationship types, reading demand, evidence kind, sequence/order, identity
  count, cohort structure, quantitative encoding, slot ranges and scope.
- `bindings.json`, capability records, class tags, local template descriptions,
  technical mappings, exclusions and permitted adjustments.
- Whether sample subject matter, incomplete prose descriptions or broad tags
  admit invalid templates or hide valid ones.
- Whether variants from one family crowd out different families that can serve
  the same job.
- Whether the catalog actually contains the alternatives the editor expected.

## Required outputs

- `reports/astra-root-cause/05-grammar-capability-audit.md`
- `reports/astra-root-cause/05-grammar-capability-audit.json`

Produce a normalized concept map from Story meaning → presentation contract →
template capability. List missing concepts, contradictory tags, stale records,
unsupported claims and capability families hidden by poor metadata.

## Acceptance

- A tag is not treated as native-fit proof.
- Unknown capability remains unknown.
- Proposed vocabulary is story-neutral and maps to observable template behavior.
- No catalog or grammar record is changed.

Stop after Job 5.
