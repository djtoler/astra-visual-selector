# Local-template technical mapping plan

Purpose: close the matching-layer evidence gap where an existing user-intake scene is present in
the candidate slate but cannot consume its already measured AE capacity because the comparison
indexes only the approved catalog.

No selection, render, API call, template redesign, or production activation is authorized by this
plan.

## Stages and acceptance checks

1. Bind local intake as an explicit comparison source.
   - The local-template registry is hash-bound in the generated comparison.
   - Duplicate scene IDs across approved and local registries fail closed.
   - Local records contribute only existing AE scene identity and family provenance.
2. Record the exact existing-project link and composition mapping.
   - `circle-list-infographic` links to the source-bound measured left project by SHA-256.
   - Scene `circle-list-infographic--scene-001` maps to native `Slide 01 Dark` only with durable
     visual and structural evidence.
   - The mapping is rejected if the measured composition ID/path or source hash changes.
3. Replay the read-only comparison and downstream harness.
   - A test proves this scene receives exact technical evidence instead of
     `technical_spec_unmapped`.
   - All existing comparison, batch-matching, and harness tests pass.
   - Selection and rendering flags remain false.
4. Record the evidence boundary.
   - Exact native capacity does not itself admit the proposal into a task slate or prove treatment
     readability/timing.
   - The current shortage count changes only if the established candidate-admission stage has
     independent task-scoped provenance.
