# Held-out semantic-split and matching integration plan

Date: 2026-09-30
Status: implementation plan; review-only integration

## Stages and acceptance checks

1. Validate the unrelated versioned StoryPackage and provider-independent split response with the existing splitter validator.
2. Convert every proposed task into the frozen VisualTask and technical-requirement interfaces without story-specific branches; preserve all truth, prohibition, data, media-kind, entity, continuity and perceptibility references.
3. Run every converted task through the reusable full-VisualTask batch matcher using existing bindings and Production Ready media.
4. Preserve unsupported media kinds as typed availability gaps instead of rejecting the story or silently mapping kinds.
5. Produce source-bound split, VisualTask, requirements, batch-match and consolidated evaluation-evidence artifacts. Keep selection/rendering false everywhere.
6. Evaluate separate declarative cases for split accuracy, requirement preservation, template fit, media availability and conditional-gap handling. Human approval may remain pending; deterministic automated categories may not.
7. Test replay, complete task coverage, requirement preservation, separate verdicts, typed unsupported-kind gaps, honest not-applicable conditional-gap status, and absence of held-out IDs in runtime code.
